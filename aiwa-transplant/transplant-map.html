NIGHT 1

Build the new X870E PC

One new chassis Friday, August 14 · the long night

Done as of Friday morning 2026-08-14: 9900X seated on the X870E under the Thermalright Secure Frame · board mounted in the Okinos · RAM in A2/B2 · 9100 PRO in M.2 slot 1 (between GPU and CPU) on the board's stock heatsink · 4060 Ti in with the anti-sag bracket · PSU bolted in, unwired · hub PWM input jumper on SYS_FAN1, hub itself not yet mounted. The AIO had not arrived yet — still scheduled for Friday.

Correction (Aug 17) — the HR-10 is not on the 9100 PRO. Earlier revisions said it was, with its fan on SYS_FAN2. It does not fit: the AIO takes that clearance in slot 1. The drive runs on the stock M.2 heatsink and idles at 35°C, so this costs nothing. The HR-10 does clear in slot 3 and goes on the SN7100 — the right allocation anyway, since that is the drive taking sustained backup writes. SYS_FAN2 is unused.

X870E follow-ups CLOSED (Aug 17). Device Manager is clean — zero problem devices, down from six. AMD PSP via Windows Update; AMDI0204/AMDI0052 via AMD Chipset 8.07.16.1035; Realtek RTL8922AE Wi-Fi + Bluetooth and both ITE8800 USB-C UCSI devices via GIGABYTE Control Center. Also: NVIDIA 595.97, Samsung Magician 9.0.1.950, and Windows 11 Pro activated (RETAIL, permanent). The AMD download turned out to be scriptable — it needed a Referer header, not a browser. GIGABYTE remains hard-blocked behind a JS challenge. Still open, non-blocking: the ChatGPT Chrome computer-use extension, which pairs with Codex only.

The SN7100 did not move on Night 1. As of Aug 17 the X870E has one disk (9100 PRO as C:) and one NIC (onboard 2.5GbE, DHCP 192.168.1.220). The 2 TB SN7100 and the Realtek 2.5 GbE card are both still in the Z690 — deliberately, so that machine stays a working rollback until the X870E has nothing left to prove. Anything below assuming D: exists, or that the 10.110.10.x direct link is up, describes a future state. Both parts move in one teardown.

The build order changed, and it matters. Earlier drafts said bench-build first and move the SN7100 in early. Both are now wrong. The board is already in the case, so there is no bench stage — and the 2 TB SN7100 must stay out until Windows is installed and booted. Windows Setup puts the EFI System Partition on whichever disk it likes when two are present; if it lands on the SN7100, the 9100 PRO stops booting the moment that drive moves, and you find out weeks later. One NVMe during Setup. That drive is also Night 2's backup target.

Read the board revision off the silkscreen (REV: 1.x, lower edge near the PCIe slot). GIGABYTE ships a different BIOS per revision and Q-Flash Plus will write the wrong one. It also decides the Wi-Fi chip — MediaTek MT7925 on rev 1.0, Realtek RTL8922AE on rev 1.1/1.2.

Mount the AIO the moment it lands — connect its PWM control cable before bolting it to the board, per ARCTIC. Radiator up top, exhaust, fans underneath pushing up, tubes out the rear. If the AIO slips, the Frost Commander 140 comes off the 13600K for the night rather than stalling the build.

Finish the fan and hub wiring per the diagram below, then wire the PSU. Set every CPU-side header to PWM in BIOS — including CPU_OPT.

POST, then BIOS: enable EXPO, confirm the 9100 PRO is seen, UEFI + Secure Boot on, fan curves set. Q-Flash Plus the BIOS if you're updating it — image renamed to GIGABYTE.bin on a FAT32 stick.

Clean Windows install on the 9100 PRO with the SN7100 still out. Use the X870E onboard LAN to the switch with DHCP for this first setup. Sign in to reclaim the license. Then drivers from the staged USB kit — AMD chipset first, reboot, then NVIDIA, then network if Windows didn't handle it, then Samsung Magician for the 9100 PRO's firmware.

Network handoff — only after the old PC is off/unplugged from the switch: move the intended NIC hardware and reconnect the same two cable roles. Set the switch adapter to 192.168.1.10/24, gateway 192.168.1.254, DNS 8.8.8.8 / 8.8.4.4. Set the direct-AIWA adapter to 10.110.10.2/30, with no gateway and no DNS; AIWA remains 10.110.10.1/30. Disconnect the temporary onboard-LAN cable, then verify gateway, Internet DNS, AIWA LAN 192.168.1.12, and direct AIWA 10.110.10.1. Static addresses are recreated on new Windows — they do not move with a cable.

Now power down and install the 2 TB SN7100 in slot 3 with the HR-10 on SYS_FAN3, plus the network card, out of the Z690. The 2 TB moves as-is — no copying, keeps its data, comes back as D:. Confirm with Get-Volume and write the letters down; Night 2 depends on them. Not done as of Aug 17 — both parts are still in the Z690.

Pull the Toshiba and retire it — the Grizzly photos are already in Google Photos, so there's nothing left on it to rescue.

Leave the Z690's 1 TB SN7100 in place and blank. It's the Proxmox boot drive on Night 3.

NIGHT 4

Cut over to the Z690

Four approval gates Next Sunday morning · ~2 hrs active, 3–4 hrs migrations

Gate 1: Stop services on ProDesk. Run the pre-flight checks in TASK4-MONDAY-BACKUP-PLAN.md — space, SMART, free sockets.

Gate 2: Begin container restore into Z690. Watch the first LXC boot.

Gate 3: Restore the host config (network, Samba, Docker compose stacks, identity state) and verify each one boots without crashing.

Gate 4: Start llama inference on the R9700, verify latency and throughput, then update the client on X870E (change Tailscale target from ProDesk to Z690). Verify one cutover call succeeds.

Shut down ProDesk. It stays built and bootable as a rollback spare.

Ends at

Z690 is production AIWA. Llama, container workloads, and network services all running on the new host. ProDesk is cold spare. You're done.
